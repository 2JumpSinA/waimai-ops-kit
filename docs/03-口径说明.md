# 03 · 口径说明：这些数字到底是什么意思

> 口径的唯一真相源是代码：`dashboard/src/lib/caliber.mjs`。
> 本文是给人看的解释。**两者冲突时以代码为准**，并请提 Issue 指出文档过时。

---

## 1. 最重要的三条

### 1.1 收入 = 预计收入，不是到账金额

| 字段 | 含义 | 能不能当收入 |
|---|---|---|
| `projectedIncome`（预计收入） | 平台按规则预估的商家应得收入 | ✅ **这是本套件的「收入」** |
| `dealAmount`（成交额） | 用户实付总额（含平台补贴、配送费等） | ❌ 不是收入，别混 |
| 结算金额 | 平台扣完佣金后实际打款 | 平台后台才有，本套件不取 |

**为什么强调**：成交额通常比预计收入高 —— 拿成交额当收入，会让老板对利润产生错误预期。

### 1.2 「近 N 天」不含今天

`last_N_days` 类窗口**截止昨天**。今日单独走「今日」窗口。

所以「近 7 天 + 今日」才是完整的 7 天。别把「近 7 天」当成「含今天的 7 天」。

### 1.3 两个平台的取消不能相加

| 平台 | 叫法 | 定义 |
|---|---|---|
| 美团 | 已取消 | `orderStatus = 9` |
| 淘宝闪购 | 流失订单 | 取消 + 全款退 |

定义不同、门店集合也不同。**相加会造出一个没有任何平台含义的数字。**

## 2. 逐项说明

### 预计收入
平台口径的商家预计所得。美团侧主字段是 `multiProjectedIncome`（多门店合计）。

### 有效订单
排除取消单后的订单数。**注意「订单数」和「有效订单数」是两个数**，看板上取的是有效订单。

### 取消率
- 不同层级的字段量纲不同：**VM/看板层是百分数**（如 `6.61` 表示 6.61%），**原始 JSON 里多为小数**（`0.0562`）
- 用错量纲的后果：差 100 倍，而且肉眼几乎看不出来

### 客单价
`预计收入 ÷ 有效订单`。**不要用成交额口径的客单价**，两者差得远。

### 推广 ROI
本套件定义为：**预计收入 ÷ 推广消耗**。

⚠️ 平台的 `convertEffectRoi`（转化效果 ROI）**不是这个口径** —— 它用转化金额做分子，会把 ROI 夸大约 3–4 倍。本套件明确不使用它。

### 推广消耗
- 美团推广（ka）：报表单位是**分**，需要 ÷100
- 淘宝闪购：账号A为「全站推广」，账号B为「斗金 BP」，**两个账号公式不同**，不能套同一个算法

### 曝光
- 平台总计 ≠ 逐店求和，实测差 7 倍左右
- 曝光数据通常是 **T+1**（昨天的数据今天才有），所以看板上会标注数据日期

### 门店营业状态
- 营业中 / 停业中
- 「异常未营业」= 停业但不在已知台账里（已知停业会被剔除，避免天天报同一批）
- 台账需要你自己维护，见 `data/plan/`

## 3. 常见误解对照

| 误解 | 正确理解 |
|---|---|
| 「收入就是流水」 | 收入是预计收入，流水/成交额是另一个指标 |
| 「今天赚了 200」 | 今天是**进行中**的，收盘前别下结论 |
| 「取消率高说明生意差」 | 也可能是平台自动取消（超时未接等），要看明细 |
| 「两个平台加起来就是总盘」 | 门店集合不同，相加无意义 |
| 「ROI 4.8 说明很赚」 | 那是平台转化口径，本套件的 ROI 口径下数字差很多 |

---

## 4. 如果你要改口径

口径常量集中在 `dashboard/src/lib/caliber.mjs`，**只改这一处**。

⚠️ 改了之后必须重跑校验（`npm test` / parity），因为看板的测试会比对字段结构。改口径不是改文案，会影响所有下游。

如果只是想让看板上显示的标签变个说法，那属于模板层（`src/template/`），不要动 caliber。
