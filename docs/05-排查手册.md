# 05 · 排查手册

> 按「你看到什么 → 是什么 → 怎么办」查。排查顺序永远是**先看登录态，再看接口，最后才怀疑代码**。

---

## A. 播报里出现「取数失败」

### A1 · 只有某一个平台失败

**最可能**：那个平台的登录态过期了。

```bash
npm run sessions
```

看输出里哪个平台不是 ✅。然后：

| 状态 | 含义 | 怎么办 |
|---|---|---|
| ✅ profile | 正常 | 不是登录态问题，往下看 A3 |
| 🟡 仅文件 / 父域票据 | 快过期，靠静态快照撑着 | 打开对应浏览器，访问一次后台首页，让票据续期 |
| ❌ 无登录态 | 真的失效了 | 双击对应 `.cmd`，在弹出的浏览器里**手动登录一次** |

### A2 · 所有平台同时失败

**先看这个**：报错里有没有 `431` 或 `400 header too large`？

- **有** → 十有八九是 **cookie 混域**。把整个浏览器 profile 的 cookie 全塞进请求，混进了其他平台的大项（动辄 1–2KB 的埋点），header 被撑爆。
  - ⚠️ 服务端报的 `header size: NNN` 是它自己的报错格式，**不是真实上限**，别照这个数字去凑。
  - 正确做法：注入前**按域过滤**，只保留目标业务域；注入**只投单域**，绝不投父域。
- **没有** → 看是不是整台机器网络断了，或两个调试浏览器都被关了。

### A3 · 登录态正常但还是失败（401 / 403 / 非法令牌）

**三个可能，按概率排序**：

1. **页面结构改版了**（最常见）→ 看 A4
2. **父域 cookie 遮蔽了正本** → 检查是否有历史注入留下的父域副本，如有需要清理
3. **账号本身被平台限制了** → 用浏览器亲自打开后台确认能正常操作

### A4 · 平台改版（最常见的长期故障）

**典型表现**：接口返回 200 但数据是空的 / 字段名对不上 / 页面能开但数字全 0。

**怎么办**：

1. 打开浏览器，F12 → Network，手动操作一次要查的功能
2. 找到那条返回业务数据的请求，看它的 URL、参数、响应结构有没有变
3. 对比 `dashboard/src/fetch-*.mjs` 里标定的接口，找出差异

**这类问题无法自动修复**，因为它是「平台变了」。本套件不承诺跟进每次改版，详见 README 的「关于维护」。

## B. 看板打不开 / 是空白

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 双击后浏览器显示一堆代码 | 文件扩展名或打开方式不对 | 确认打开的是 `.html` 文件，用浏览器打开 |
| 打开是白屏 | 构建失败，生成的 HTML 不完整 | 重跑构建命令，看输出里有没有报错 |
| 能开但图表空白 | 某个平台数据缺失，且渲染层没降级好 | 这是 bug，请提 Issue 并附上构建输出 |
| 打开很慢 | 文件较大（含内联 echarts 和数据） | 正常，等几秒 |

## C. 播报没发出来

按这个顺序查：

1. **手动跑一次播报脚本**，看能不能发出去
   - 能发 → 是计划任务没生效（见 C1）
   - 不能 → 是 webhook 或凭据问题（见 C2）
2. **看日志**：`broadcast/logs/` 下当天的日志

### C1 · 计划任务没生效

```powershell
schtasks /query /tn "WaimaiDailyBroadcast" /v /fo LIST
```

看「上次运行结果」和「下次运行时间」。常见原因：

- 电脑在计划时间处于**休眠/关机**状态 → 改成唤醒执行，或干脆别让它休眠
- 任务注册时用了非管理员账号 → 用管理员身份重新注册
- 任务里的路径写错了 → 重新注册

### C2 · webhook 问题

1. 检查 `config.json` 里的 webhook 地址是否完整
2. 在企微群里重新获取一次 webhook（群设置 → 群机器人），替换后重试
3. 注意：企微机器人有**发送频率限制**，短时间内发太多会被限流

## D. 数字看起来不对

**先别怀疑代码，先怀疑口径。**

| 你可能看到的 | 实际情况 |
|---|---|
| 「今天才 200 块，昨天有 2500」 | 今天是**进行中**的一天，不是整天。要比就比「同时段」 |
| 「成交额和收入对不上」 | 成交额 ≠ 预计收入，是两个指标 |
| 「取消率 0.0562」 | 量纲问题：某些字段是小数，某些是百分数 |
| 「美团和闪购加起来对不上」 | 两平台取消单定义不同，**不能直接相加** |

详见 [`03-口径说明.md`](03-口径说明.md)。

## E. 通用排查纪律（照这个做能少走 90% 的弯路）

1. **别一上来就重登**。先用 `npm run sessions` 看登录态，很多时候是票据问题，自愈一下就好
2. **别按进程名看内存/进程** —— 机器上可能有好几个 Chrome 实例，要按进程树看
3. **改了代码先跑校验**，不要直接上生产。看板有静态校验，改了模板必须重跑
4. **报错日志要留全**。提 Issue 时贴完整报错，不要只写「用不了了」
5. **一次只改一个变量**。同时改三处，出问题就不知道是哪处

## F. 什么时候该停下来找人

出现以下情况，别自己硬碰，直接提 Issue 或找懂行的人：

- 按平台判定的「账号被限制」（后台登录不进去、提示违规）
- 需要修改登录态相关的 cookie 操作（做错会导致整站不可用，恢复要重登所有账号）
- 平台改版导致接口全变（这不是配置问题，是代码要改）
