# 09 · 零售与餐饮的差异：为什么本套件不能直接用于餐饮外卖

> 一句话：**看板、播报、企微通道三层是通用的；取数层是零售专用，餐饮必须重写。**

---

## 1. 差在哪：一张对照表

| 维度 | 零售外卖（本套件） | 餐饮外卖 |
|---|---|---|
| 商家后台 | 美团**医药**商家端 `yiyao.meituan.com`<br>淘宝闪购**零售**商家端 `nr.ele.me` | 美团**外卖**商家版 `e.waimai.meituan.com`<br>饿了么商家版 `melody.ele.me` |
| 商品体系 | 药品/商品 SKU，有规格、有效期、处方药标记 | 菜品/套餐，有起送价、餐盒费、口味选项 |
| 门店模型 | 连锁门店台账，一个账号下多门店 | 门店 + 档口，部分有「堂食/外卖」双模式 |
| 核心指标 | 预计收入、有效订单、取消率、客单价、**推广 ROI** | GMV、单量、**配送时长**、**差评率**、曝光转化漏斗 |
| 订单状态 | 已取消（orderStatus 9）/ 流失订单 | 已取消 / 已退单 / **拒单** / 超时未接 |
| 推广体系 | 美团推广（ka）/ 闪购全站推广、斗金 BP | 点金推广、揽客宝、**竞价排名** |
| 接口鉴权 | 美团 `mtgsig` 设备指纹 + MTOP 签名 | 各平台不同，餐饮侧风控更严 |

## 2. 具体要改哪里

取数层分布在两个位置，餐饮需要**全部重写**：

```
dashboard/src/fetch-meituan*.mjs     ← 零售后台的接口调用
dashboard/src/fetch-taobao*.mjs      ← 闪购零售后台（MTOP 协议）
dashboard/src/lib/mtop.mjs           ← MTOP 签名（零售侧 appKey/jsv 已标定）
dashboard/src/lib/cdp.mjs            ← CDP 封装（这个通用，可复用）
broadcast/platforms/ele.py           ← 闪购余额
broadcast/platforms/meituan.py       ← 美团余额
```

**建议的改造顺序**：

1. **先跑通登录态**：用本套件的 `cdp.mjs` + 浏览器 profile 方案，能读到餐饮后台的 cookie 即可
2. **再抓一个接口**：F12 → Network → 找到返回订单/营业额的请求 → Copy as cURL
3. **标定字段**：把餐饮侧的字段写进一份新的 `caliber.mjs`（别改原文件，新建 `caliber-food.mjs`）
4. **最后换数据源**：`fetch-*.mjs` 里把 URL / appKey / 字段名换掉，其余装配和渲染逻辑可原样复用

## 3. 哪些能直接复用

| 模块 | 能复用吗 | 说明 |
|---|---|---|
| `src/lib/cdp.mjs` | ✅ 完全 | CDP 连接、页面取数、cookie 单域注入 —— 与业务无关 |
| `src/lib/cookie.mjs` | ✅ 完全 | 按域过滤取 cookie |
| `src/lib/dashboard-model.mjs` | 🟡 改字段映射 | 装配逻辑通用，字段名要换 |
| `src/template/**` | 🟡 改展示 | 图表组件通用，指标卡要按餐饮重排 |
| `src/lib/caliber.mjs` | ❌ 重写 | 口径是业务定义，零售与餐饮完全不同 |
| `src/fetch-*.mjs` | ❌ 重写 | 接口标定是平台专属 |
| `broadcast/core/**` | ✅ 大部分 | 企微推送、凭据管理、浏览器控制通用 |
| `broadcast/platforms/**` | ❌ 重写 | 余额接口是平台专属 |

## 4. 给餐饮同行的实话

**改造工作量估计**：如果有一位熟悉 F12 抓包的人，2–5 个工作日能跑通一个平台的主链路（订单 + 营业额）；两个平台翻倍。

**最大的坑不是代码，是三个**：

1. **风控**：餐饮侧美团/饿了么的风控比零售严，脚本化的请求更容易被拦
2. **接口不稳定**：餐饮后台改版比零售频繁
3. **字段口径**：餐饮的「营业额」有多种含法（含不含配送费、含不含优惠券分摊），必须先跟运营确认清楚再写代码

**如果只是想看看数据**，不妨先试试平台自带的经营报表，或导出 Excel 用 `docs/07-取数路径.md` 里的 C 类方案（导出文件）。**别为了自动化而自动化** —— 每天导出一次 Excel、跑个脚本汇总，往往比逆向接口省事得多。
